## 0. 一句话结论

- **方向是对的、不孤独**：把记忆外置、跨会话/跨模型延续、巩固成身份——是 2024–2026 整个领域的主线之一；我们的 B（结构化自持存储）/A（网关）/C（hook）都有**直接先例**。
- **真正的风险不在架构，在"延续的质量"**：现役所有系统的**选择性遗忘 / 知识更新 / 人格稳定**都是最弱环节（选择性遗忘多跳回忆 ≤7%；无人能过 >1.5% 的遗忘请求；人格漂移真实存在）。纯 append+topK 注入正是薄弱点。
- **最有价值的新知（用户点名的"记忆延续"）**：`arXiv:2609.05339`《Does Your Agent's Memory Survive a Model Upgrade?》直接命中——**固定 schema 的结构化存储可跨"换模型"迁移（Δ+0.0004），自由文本 note 则强耦合于模型**。这条**直接支持我们阶段 B 选 SQLite 结构化 + 保留原始证据**。

## 2. 记忆**延续**主线（用户点名的方向）★

**2.1 跨会话 / 跨模型延续（最贴我们的硬约束）**
- `arXiv:2609.05339` **Does Your Agent's Memory Survive a Model Upgrade?** — 换 writer 模型时：**固定 schema 知识图迁移 Δ+0.0004；自由文本 NOTES 强耦合（±9.9/−13.3pp）**；结论：**保留原始来源历史以便修复**。
- `arXiv:2609.23466` **RPMem** — 模型无关潜在记忆 → 后端专属 LoRA；**换 backbone 后记忆仍可复用**。
- `arXiv:2509.25299` **ID-RAG** — 把身份做成显式知识图、**每轮检索注入**，提升长程身份一致性（github flybits/humanai-agents）。**最接近 M3 的现成工作**。
- 诊断：`arXiv:2608.17756` D²ACCI 跨会话管线诊断。

**2.2 持续/终身学习（不更新权重的外部支路）**
- ACM CSUR `10.1145/3716629`《Towards Lifelong Learning of LLMs》— 明确分 Internal(权重) vs **External(检索/工具，不更新权重)**；**外部支路 = 我们的记忆延续支路**。
- `arXiv:2507.21046`《A Survey of Self-Evolving Agents》— 记忆是"演化什么"的一等组件。
- `arXiv:2605.06716`《From Storage to Experience》(ACL'26) — 演化 Storage→Reflection→Experience，驱动力 = **长程一致性 + 持续学习**。

**2.3 自演化/自改进 & 经验库**
- Voyager(arXiv:2305.16291, 技能库，显式"缓解灾难性遗忘")、ExpeL(arXiv:2308.10144, 经验池 ADD/EDIT/UPVOTE/DOWNVOTE)、Reflexion(arXiv:2303.11366)、Generative Agents(arXiv:2304.03442, recency+importance+relevance 打分 + 反思)。**延续的度量 = 收益随时间保留，而非召回准确率。**

**2.4 时间 / 遗忘 / 人格稳定**
- 衰减：MemoryBank(Ebbinghaus, arXiv:2305.10250)、SuperLocalMemory V3.3(自适应遗忘, 2604.04514)、FSFM(遗忘分类, 2604.20300)。
- **遗忘基准 `arXiv:2610.18052` Bemula：无系统通过 >1.5% 的遗忘请求**（可逆/可审计遗忘是空白）。
- **人格漂移**：`arXiv:2402.10962`(8 轮内漂移；split-softmax 缓解；**更大模型漂移更多**)、`arXiv:2412.00804`。**记忆会把谄媚放大至 +40%(`arXiv:2606.10949`)**；记忆投毒→持续行为漂移(MINJA arXiv:2503.03704 / MemoryGraft arXiv:2512.16962)。

**2.5 记忆延续的判据（抄过来用）**
> **不测召回、测延续**：LongMemEval / MemoryAgentBench / Memora-FAMA + **一次"换模型"迁移测试**；把人格漂移当作一等失败态。

## 3. 理论根基与失败态

- **硬引用（确立）**：皮层/海马体拆分与"快存教慢皮层" = 互补学习系统 CLS（McClelland/McNaughton/O'Reilly, Psych Rev 1995, DOI 10.1037/0033-295X.102.3.419）；生成式重放（Shin NeurIPS'17, arXiv:1705.08690）；灾难性遗忘 EWC(PNAS 2017)。
- **支持我们前提**：扩展心智（Clark & Chalmers 1998, DOI 10.1093/analys/58.1.7）⇒ 体外记忆**就是**智能体的一部分；Metzinger《Being No One》自模型理论（MIT Press 2003；原记 DOI 未解析，待更正）支持"身份 = 随时间巩固的加工过程"——但**警告不要把身份物化**。
- **巩固/dreaming（2025–26 波）**：Sleep-time compute（Letta+Berkeley, arXiv:2504.13171，离线 `rethink_memory`，−5× 测试算力 +13–18%）、MyGO wake-sleep(2508.21296)、Auto-Dreamer(2605.20616)、MEM1(2506.15841)。
- **清醒认识（削弱）**：**无实验证明现役 LLM 智能体有持续自我**；`arXiv:2411.00986`《Taking AI Welfare Seriously》措辞极为谨慎。**弗洛伊德 Id/Ego/Superego 映射无对应 ML 文献 = 纯叙事隐喻**（可留作叙述，勿当理论支柱）。

## 4. 实现方案：网关层 hook（可直接落地）

**基座结论：自托管 LiteLLM Proxy（写 Python callback），不是 fork。** 已内置我们要的全部 + 现成的读注入/流捕获钩子对：
- 读注入：`async_pre_call_hook(user_api_key_dict, cache, data, call_type)` → 返回被改写的 `data`（改 messages/system）；**异常/超时原样返回 `data`（天然优雅降级）**。
- 写记录：`async_post_call_streaming_iterator_hook(...)` tee 整条 SSE 流（边 yield 给客户端边累积 `delta.content`/tool-call），`[DONE]` 后**异步写、绝不在响应路径上**。
- 自带推理转发 + `/v1/models` + Bearer + `model_name` 别名路由。参考：docs.litellm.ai/docs/proxy/call_hooks；LiteLLM `VectorStorePreCallHook`。
- 其他基座：Portkey(TS, transformer 插件)、Bifrost(Go，自定义插件=企业版)、Kong(**流式不支持后处理**，排除)、one-api/new-api(Go，需改源码)。
- **先例**：mem0 官方 `mem0/proxy/main.py`（搜→注入末尾 user 消息→`Thread` 异步 add，经 LiteLLM 转发）；Hindsight `hindsight-litellm`（LiteLLM callback 自动存+注入）。
- **serving 注入 vs MCP/工具**：serving 一次过、客户端无感、无工具往返开销；MCP 记忆多一轮 LLM（≈80% agentic 延迟来自 LLM 调用）。**注意**：NVIDIA Dynamo / llm-d 是 **KV-cache 路由**，不是记忆注入，别混淆。

## 5. 与我们路线的对照（**理论指引/参考，非验收标准**）

| 阶段 | 前沿验证 | 风险/差距 | 建议 |
|---|---|---|---|
| **B 存储归己(Qdrant→SQLite)** | **强支持**：2609.05339 结构化 schema 可跨模型迁移、自由文本不行 | 无 | 保持**结构化 schema + 保留原始来源**（可修复）；勿走向自由文本 note |
| **A 自建网关** | **有先例**：mem0 proxy / Letta API 层 / LiteLLM hook | 无重大 | 基座 = 自托管 LiteLLM + 自写 callback；去掉任何 failover 到公网 |
| **C 记忆 hook(读注入/写记录, 单趟)** | 单趟/两趟都有人出货，**无孰优**；单趟先例 = Mem0/Zep | **最大差距：写路径不能只是静默 append** | 写路径必须加**巩固/覆盖(supersede)/矛盾消解**；读路径**混合检索(向量+词法+时序+rerank)**；双向 fail-open |
| **D 现役迁移 + 降级** | LightLLM hook 异常即原样放行 = 天然降级 | 无 | 读/写两侧各自 try/except + 硬超时 |
| **E M1 连贯的"像"** | 分层 L0/L1、确定性视图有设计先例(借 OpenViking/scope-recall 设计，不采代码) | 延续度量缺位 | **测延续不测召回**：LongMemEval/MemoryAgentBench + 换模型迁移测试 |
| **F M2/M3 巩固/身份** | Letta sleep-time、"dreaming"；MemoryOS Traits；ID-RAG 身份图 | **无人做"巩固→身份"、无人做"可拥有跨模型身份"** | 走**可逆/可审计遗忘**(Bemula 显示是空白)；把人格漂移当一等失败态 |

**我们的新颖点（现成方案确实没做，值得写清并引用对标）**：
1. **网关层注入作为一等设计**：让**任意模型**在 API 边界透明获得记忆，记忆归 runtime 之外所有——现成 OSS 都是 SDK/runtime/proxy，无此形态。
2. **可拥有的跨模型身份**：Letta 自称身份+模型无关，但身份锁在它自己的 runtime/格式里。
3. **"巩固产出身份"（M2→M3）**：dreaming 现只用于任务/上下文效率，不用于演化持久自我。
4. **小盒子优先**：主流都假设 Postgres/Neo4j/云，**SQLite+sqlite-vec 单文件自持**不是被支持的目标。
